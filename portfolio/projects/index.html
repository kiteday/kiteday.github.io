프로젝트

현업의 작업과 제약을 파악해 시스템으로 옮기고, 실제 사용이나 검증 범위를 확인했습니다.

현업 AX와 중앙 플랫폼상담 정책 동기화퀴즈 제작 도구AI 초상화 전시DayTD 코디 추천

03 / Engineering projects

현장의 문제를 시스템으로

성과와 한계를 함께 적었습니다. 프로토타입을 운영 성과로 표현하지 않았습니다.

01 / WORKFLOW & PLATFORM

개인 자동화에서 팀이 공유하는 실행 환경으로

무신사에서 비개발 조직의 반복 업무를 자동화했습니다. 실제 사용이 시작되자 개인 노트북과 Skill 파일에 묶인 방식이 다음 문제로 드러났습니다.

공통 도구 현업 사용 · 플랫폼 프로토타입 검증

OBSERVE

9개 부서의 작업을 다시 보았습니다

업무 화면을 녹화해 입력, 데이터 출처, 수작업 판단을 분리했습니다. 서로 다른 요청에서 Databricks 조회와 데이터 가공이 반복되는 것을 확인했습니다.

BUILD

각자의 권한으로 쓰는 공통 도구

개인 토큰 기반 Databricks 로컬 MCP와 설치 스크립트·가이드를 개발해 배포했습니다. 업무별 Skill과 Routine은 시안을 보여준 뒤 담당자가 핸즈온에서 직접 만들도록 도왔습니다.

EXTEND

중앙 실행과 팀 공유를 검증

노트북을 닫으면 Routine이 멈추고 Skill 변경 때마다 파일을 수기로 공유해야 했습니다. 동료와 구조를 설계하고 HLD를 작성해 중앙 플랫폼 프로토타입으로 확장했습니다.

제 역할. 현업 업무 분석, 로컬 MCP·설치 도구 개발과 배포, 핸즈온 코칭. 중앙 구조는 동료와 함께 설계했고 HLD와 인프라를 포함한 프로토타입 구현·검증을 맡았습니다.

결과의 범위. 로컬 도구는 현업이 실제 사용했습니다. TF 전체에서 23건이 현업에 적용됐고, 주 928인시는 실측과 추정이 섞인 TF 전체 절감 규모입니다. 중앙 플랫폼은 현업 공개 전 프로토타입입니다.

02 / SYSTEM INTEGRATION

상담 정책 문서의 형식과 권한을 함께 옮기다

상담 운영팀은 사내 위키의 정책 문서를 외주 상담사가 쓰는 Salesforce 지식 베이스에도 수기로 게시했습니다. 변경 감지부터 갱신까지 연결하면서 문서 손실과 변경 권한을 해결했습니다.

개발팀 샌드박스 검증 후 인계

UNEXPECTED FAILURE

HTML을 그대로 옮기자 이미지가 깨졌습니다

두 시스템의 문서 형식이 달랐습니다. 원본 이미지 저장소에서 파일을 읽어 대상 시스템으로 스트리밍 전송·저장하고, Python으로 본문을 변환한 뒤 대상 시스템의 이미지 태그로 다시 연결했습니다.

OPERATIONAL RISK

자동화가 수정할 범위를 좁혔습니다

운영팀·담당 개발팀과 게시 기준과 위험을 검토했습니다. 관련 지식 베이스만 수정할 수 있는 전용 계정을 마련하고, 문서 ID를 기준으로 수정된 위키 문서가 기존 문서를 갱신하도록 연결했습니다.

검증. 개발팀이 마련한 두 개발 환경에서 여러 문서를 게시·수정했습니다. 게시 성공, 본문·이미지·표 표시, 원본 위키의 문서 계층 반영과 기존 문서 갱신을 확인했습니다.

인계 범위. 검증한 코드와 현업 PC 설정용 Skill을 전달했습니다. 인계 후 현업의 실제 운영 실행 여부는 확인하지 못했습니다.

03 / PRODUCT DELIVERY

매일 만드는 퀴즈의 판단 기준을 제품 규칙으로

담당 마케터가 발행된 콘텐츠를 찾아 읽고, 퀴즈 소재와 문제를 직접 정하던 업무를 AI 기반 제작 도구로 옮겼습니다. 2-pager부터 설계·개발·운영 배포까지 담당했습니다.

운영 배포

POLICY

정답보다 먼저 규칙을 정했습니다

담당자와 콘텐츠당 퀴즈 한 개, 사용 콘텐츠의 7일간 재사용 금지를 합의했습니다. 운영 정책은 PRD에, 구현 구조는 HLD에 정리했습니다.

IMPLEMENT

중복을 콘텐츠 ID로 판단

내부 API에서 가져온 콘텐츠 ID를 Redis에 7일 저장했습니다. 정답에 브랜드명이 노출되지 않도록 작성 규칙을 프롬프트에 반영했습니다.

RELEASE

현업 검토를 거쳐 배포

생성 결과를 2주간 담당자에게 보여주며 수정한 뒤 운영에 배포했습니다. 퀴즈 생성 약 30초를 실측했고, 최종 검토·발행은 사람이 맡았습니다.

04 / INTERACTIVE EXHIBITION

AI 초상화를 관람객이 직접 쓰는 작품으로

학부에서 수집·정제한 약 12,000장의 이미지로 초상화 생성 모델을 만든 뒤, 조형예술 전시에서 관람객 사진을 변환하는 체험형 작품으로 확장했습니다.

전시 · 80명 이상 체험

MODEL & DATA

데이터 품질부터 다시 다뤘습니다

이미지를 수집·필터링하고 팀과 함께 오류를 검수했습니다. 같은 평가셋에서 분류 정확도는 43%에서 66%로 올랐고, StyleGAN2로 초상화 생성 결과를 만들었습니다.

SERVICE CONSTRAINT

전시 PC의 추론 지연을 해결했습니다

전시 PC에서 일부 계산만 해도 대기가 길었습니다. 추론을 성능이 높은 서버 컴퓨터로 옮기고 FastAPI로 화면·파일 연동을 완성했습니다. 현장 반복 관찰에서 대기가 10분 이상에서 대체로 2분 이내로 줄었습니다.

협업 범위. 팀원이 서버 네트워크 접근의 기초를 만들었고, 저는 화면과 파일 연동을 이어서 완성했습니다. 전시는 미술·공학 전공자를 포함한 팀과 함께 준비했습니다.

공개 근거. 초상화 변환기 코드 ↗. 대기시간은 계측 로그가 아닌 현장에서 여러 번 관찰한 대략적 범위입니다.

05 / UNDERGRADUATE PROJECT

DayTD · 날씨에 맞는 코디 추천

학부 때 4인 팀의 팀장으로 참여해, 날씨와 사용자의 취향을 반영하는 코디 추천 시스템을 기획하고 백엔드·AI 모델을 담당했습니다. 연구 모델을 사용자가 선택하고 저장할 수 있는 웹 서비스로 연결한 경험입니다.

2022.04–11 · 팀 프로젝트

PRODUCT

날씨와 사용자 취향을 연결

지역별 날씨를 반영한 추천, 마음에 드는 옷의 저장·재추천 흐름을 팀과 함께 정의했습니다. 일정과 역할은 WBS와 이슈로 관리했습니다.

DATA & MODEL

의류 분류를 다시 설계

K-Fashion 데이터의 세부 의류·스타일 라벨을 8개 카테고리로 재구성하고, 부적절한 이미지를 정제했습니다. 경량 MobileNet을 추천 모델에 활용했습니다.

DELIVERY

웹 서비스와 수상

Django·React·MySQL·TensorFlow를 사용했습니다. KT AI 경진대회 TOP3와 교내 캡스톤디자인 대상을 기록했습니다.

제 역할. 팀장으로 방향과 일정을 조율하고 백엔드와 AI 모델 개발을 담당했습니다. 프론트엔드는 팀 협업 결과입니다.

공개 결과. GitHub 코드와 시연 자료 ↗ · 서비스 시연 영상 ↗. 처리 시간 수치는 자료마다 기준이 달라 이 페이지에 기재하지 않았습니다.
